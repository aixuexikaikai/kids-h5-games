# Architecture audit v1.0

审查时间：2026-09-26。初始当前工作目录为空，无 package.json、源码、AGENTS.md 或素材；未删除或覆盖任何原工程。补充读取三个已知历史交付 HTML，保留在工程外 legacy/。这不是对所有历史游戏的全量迁移。

## 问题归因

| 历史反馈 | 审查判断 | 底层处理 |
| --- | --- | --- |
| 主角不显示、黑白屏、加载失败 | 资产完成状态与循环分散；不是本次已复现的全部旧故障 | 资产加载超时/错误界面、必需资源校验、统一 boot |
| 人物太小、变形、风格不符 | 公园 fit 存在非等比缩放；风格问题须人工看图，不能仅代码断言 | 固定逻辑坐标、contain 视口、等比图集绘制、原素材清单 |
| 小按钮、重复层、截图按钮 | Canvas UI 随画布缩小；背景遮盖是单游戏补丁 | DOM 唯一 UI 层、实际 CSS 像素命中区、安全区、干净独立背景 |
| Boss 越界、矮怪打不到、碰撞错位、子弹穿透 | 各项目碰撞坐标不同；公园有扩大碰撞修补 | 底部中心锚点、归一化碰撞体、范围校验、扫掠子弹、可达性 QA |
| 难度突增、Boss 过厚 | 关卡数值问题；医院 Boss HP 460–700 | DifficultyConfig 与 Boss 阶段配置；Demo 低伤害、高容错 |
| 死亡/技能/关卡状态异常 | 多个函数直接修改 mode 与数组 | 状态机、幂等死亡事件、统一清场、技能恢复 |
| 金币只改数字/不能拾取 | 公园直接记余额；医院 v1.3 已有实物掉落 | 移植掉落/散落/移动拾取流程，仅拾取入账 |
| 购买、解锁、初始武器错误 | 医院已支持空手，但装备不存；多次存盘中间态 | 配置初始武器，购买与余额单次保存，持久装备 |
| 变身不明显 | 美术形态与配置问题，不能由色调特效解决 | 独立素材、尺寸、碰撞体、技能、速度、持续时间 |
| 解锁重复、刷新丢进度 | 金毛无存档；其余 key/结构不一致 | gameId + version 隔离、去重、损坏恢复、写入失败提示 |

## 复用与废弃

保留 Canvas 技术路线；医院版图集和背景逐字节提取，不重绘。移植 sprite 的 height×cropWidth/cropHeight 等比公式与底部锚点；复用医院版多 pointerId→动作映射/失焦释放思路、金币散落重力/移动拾取流程、无敌帧及目标中心辅助瞄准。这些函数改写为独立模块，非原封不动复制整段闭包。

不纳入新引擎：全局共享 mode、UI 内购币逻辑、截图背景遮盖、矮怪专用 topAssist 魔法数、按版本命名的零散存档 key。旧文件保留，未实际删除。金毛的奶酪搬运/双轴玩法暂不迁移。

## 重构方案

使用原生 Canvas 2D + ES modules（JavaScript），零运行依赖；Node 内置服务/测试，Playwright 仅用于开发 QA。无需 Phaser/PixiJS 迁移。Game 编排纯逻辑系统；SceneManager 独占状态转换；DOM UI 只发命令；逻辑世界固定 1280×720，显示等比映射；从配置注册素材、角色、技能、武器、敌人、Boss、关卡、难度与解锁。

先实现横版单地面 arena 的最小实用引擎。平台地形、俯视守护、塔防和格斗专用规则不伪装成已支持；可在共享输入、素材、经济、存档基础上另接玩法系统。

## 风险

- 历史代码没有模块和测试，需用新测试约束迁移，不能证明所有历史 Bug 均复现或修复。
- 已检查医院主角原图为空手，Demo 沿用；公园变身图含烘焙背景，不适合作透明角色；Demo 变身改用医院原武器图集里的独立妈妈守护者形态，与主角保持同素材包。
- 移动浏览器全屏与持久化由环境决定；失败须可见，不以黑屏代替。
- 自动浏览器覆盖尺寸和触控，不等同于小米/iPhone 实机验收。
- 本阶段不覆盖所有旧游戏自动迁移，也不引入服务器账户存档。
